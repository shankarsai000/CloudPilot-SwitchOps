DESIGN DECISIONS
================================================================================

1. Sync I/O + ThreadPoolExecutor (NOT async)
   Reason: Cloud SDKs are blocking; simpler error handling; easier to test

2. Unified Resource Schema (CloudResource)
   Reason: Single source of truth; type-safe; enables generic queries

3. Repository Pattern for Persistence
   Reason: DB abstraction; testable; easy to swap backends

4. Graceful Partial Failures
   Reason: Real-world environments are multi-cloud; one cloud down ≠ fail all

5. Dependency Injection for Cloud Clients
   Reason: Testable; supports multi-account scenarios; no hidden state

6. Deduplication by (provider, region, resource_id)
   Reason: Later discoveries override earlier ones (simple, predictable)

See README_M1_IDA.md for detailed rationales and trade-offs.
